# Lead Management Automation (n8n)

Local automation that captures sales leads through an HTTP webhook, validates the payload, scores the lead, and stores it in PostgreSQL.

This is a portfolio project focused on workflow design, HTTP status codes, and data integrity. The workflow is built and tested by hand in n8n; the JSON export documents the result.

## Stack

- n8n (self-hosted, Docker)
- PostgreSQL 16
- Docker Compose

## What the endpoint does

`POST /webhook/lead`

| Case                          | HTTP | Body                                 |
| ----------------------------- | ---- | ------------------------------------ |
| Valid new email               | 200  | Inserted row (`id`, `lead_score`, …) |
| Missing `fullName` or `email` | 400  | `fullName and email are required`    |
| Email already stored          | 409  | `email already exists`               |
| Database error                | 500  | `could not save lead`                |

Lead score (before insert):

- +20 if `company` is present
- +20 if `interest` is `Demo`
- +10 if `country` is present

`email` is unique and stored in lowercase. `Jane@x.com` and `jane@x.com` are the same lead. `id` is generated by the database (`SERIAL`). Do not send `id` on insert.

## Run locally

```bash
docker compose up -d
```

Editor: http://localhost:5678

Editor login (local): `admin` / `admin123`

A fresh n8n 2.x container may ignore `N8N_BASIC_AUTH_*`. If that login fails, create the owner user on first open.

In n8n 2.x, production webhooks require **Publish**. Test URL (`/webhook-test/lead`) is only for the editor. Recruiters and clients should call the production URL.

Production: `http://localhost:5678/webhook/lead`

## Database

Create the table after the containers are running.

Linux or macOS:

```bash
docker exec -i lead-postgres psql -U postgres -d lead_management -f - < sql/001_create_leads.sql
```

Windows PowerShell:

```powershell
Get-Content .\sql\001_create_leads.sql | docker exec -i lead-postgres psql -U postgres -d lead_management
```

Example credential inside n8n (local lab only; same values as `docker-compose.yml`):

- Host: `postgres`
- Database: `lead_management`
- User: `postgres`
- Password: `postgres123`
- Port: `5432`

Import `workflows/lead-capture-webhook-to-postgres.json`, attach this credential to the Postgres node, then **Publish**. The workflow export stores the credential name only, not the password.

## Test

curl:

```bash
curl -s -w "\nHTTP:%{http_code}\n" -X POST http://localhost:5678/webhook/lead \
  -H "Content-Type: application/json" \
  -d "{\"fullName\":\"Jane Doe\",\"email\":\"jane.doe@email.com\",\"company\":\"Acme\",\"country\":\"US\",\"interest\":\"Demo\",\"message\":\"Hello\"}"
```

Duplicate email should return HTTP 409. A body without `email` should return HTTP 400.

PowerShell 5.1: `Invoke-WebRequest` throws on 4xx. Read the body from `$_.ErrorDetails.Message`.

## Workflow file

`workflows/lead-capture-webhook-to-postgres.json`

## Email notification

On HTTP 200 only, the workflow sends an email with the lead name, email, company, and score. Respond 200 is wired beside the Gmail node, so the API returns the inserted row, not the Gmail response.

The exported recipient is `sales@example.com`. After import, set your own address on the Gmail node. The export stores the credential name only. Do not commit client secrets or tokens.

## Known limits

This is a local portfolio lab, not a production deploy. The webhook has no authentication. Lab passwords live in `docker-compose.yml`.
